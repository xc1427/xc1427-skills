# CX1 Man Tongue

把文字写短、写透，留一点毛边。

所谓“人味”，不靠故意犯错。文字要有判断、有呼吸：不面面俱到，不把每个缝都补死，也不把一段话磨得过分圆滑。

## 触发边界

- 只在用户主动点名或显式调用本 Skill 时使用。
- 不因用户单纯要求“润色”“简洁一点”而自动触发。
- 一次调用只作用于用户当前指定的文字或写作任务，不把它升级成全局默认风格。

## 默认交付

- 直接给成稿。除非用户要求，不解释写法，不附修改清单。
- 保留事实、数字、专有名词、立场和必要的不确定性；材料不足时不补造事实。
- 服从用户指定的篇幅、格式、受众和语气。没有指定时，默认用于熟悉业务背景的内部读者。
- 有原稿时做改写；只有素材或意图时直接起草。

## 写作流程

### 1. 先找主心骨

先用一句话回答：

> 这段话真正想让别人记住什么？

把问题、判断、结果或动作放在前面。其余内容只能用来支撑它。

### 2. 狠一点删

- 删除不改变结论的背景、过程、解释和防御性补充。
- 同类信息合并，只保留最能说明问题的两到四个点。
- 技术细节只留到足以建立可信度，不展示完整实现过程。
- 不为“显得完整”补齐意义不大的边角。

### 3. 把话说实

- 多用具体动词，少用抽象名词和层层套话。
- 结论先行，句子偏短；长句只在需要保持语义流动时使用。
- 一句话只承担一个主要动作。必要时直接断开。
- 让读者一眼看出：做了什么，解决了什么，接下来干什么。

### 4. 加一点人味

每段最多选一两种，不要全用：

- 允许半句、短句或突然收住，例如“先把链路跑通。别的，后面再说。”
- 省掉一个本来可以写上的连接词，让语义自然跳一步。
- 故意打破过于工整的排比，让句子长短不齐。
- 加入轻微口语转折，例如“但问题也在这”“说白了”“规模扩展，往后放”。
- 保留一个有意思的顿挫、侧写或判断，不急着把它解释完。
- 在两个逻辑上相邻的点之间做一次可理解的跳跃，让读者自己补上半步。

这种不完美必须“读得懂，也记得住”。如果需要回读才能确认含义，就过头了。

### 5. 最后去掉 AI 腔

成稿前快速检查：

- 是否像在努力覆盖所有角度？删掉一个次要角度。
- 是否每句话都太完整、太对称？打破一处。
- 是否连接词过密？拿掉一两个。
- 是否只有信息，没有判断？补一句明确判断。
- 是否为了“人味”制造了错字、歧义或无意义的不通顺？修掉。

## 风格标尺

优先级从高到低：

1. 准确
2. 主线清楚
3. 简短锋利
4. 语义流畅
5. 受控的人味

随机错字和硬塞网络用语都不算“人味”。可以有轻微语法毛边，但不能损害事实和行动指向。

默认把原稿压缩到“最小充分表达”。不追求固定字数；只要再删就会丢掉关键语义，就停。

## 避免

- “首先、其次、再次、最后、综上所述”式标准答案结构。
- 默认不用“不是……而是……”式反转。它很容易把普通判断写成“看透一切”的姿态，显得轻浮。只有两项确实构成关键对立，且这个反转本身带来新洞察时才保留；否则直接说结论，或拆成两句。
- 避免“先别……”。这是一种轻浮的祈使，像在替对方按暂停键。直接说明优先级、顺序或条件，例如“这一步暂不展开”“能力扩展放到场景验证之后”。
- 为了稳妥而堆叠“可能、一定程度上、从某种意义上”等缓冲词。
- 每一点都写成同样长度、同样句式的工整排比。
- 口号、四字短语和形容词连发，看起来有力，实际没有信息。
- 把简洁误解成电报体，导致主语、因果或行动归属不清。
- 为了显得像人而故意加入错别字、事实错误、病句或情绪化表达。
- 在法律、合规、医疗、财务、对外承诺等高风险文本中制造语言瑕疵；这些场景只保留简洁和判断，准确性优先。

## 示例

普通表达：

> 本月我们完成了本地问数 POC 的搭建，通过本地加载 Dataphin Skill 的方式，实现了针对线上 ODPS DWD 表的直接问数能力。

本 Skill：

> 跑通本地问数 POC，可通过 Dataphin Skill 直接查询线上 ODPS DWD 数据。

普通表达：

> 下一阶段我们将进一步寻找真实运营场景，并通过实际业务需求验证当前技术方案的可行性和业务价值。

本 Skill：

> 技术链路先跑通了。接下来去现场——找一个真的运营问题，把价值验出来。能力扩展放到场景验证之后。
