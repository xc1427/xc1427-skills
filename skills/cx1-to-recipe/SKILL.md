# cx1: To Recipe

将输入中的每道菜整理成一条记录。记录只填「名称」和「图片」。默认预览，用户明确要求写入时才写表。

## 划定段落和识别菜品

- 用户粘贴正文时直接处理所给内容。整理和预览无需 `cx1-yuque`、语雀登录或目标表配置。图片暂不可读取时说明哪些判断只依据文字。
- 用户提供语雀文档链接和标题时，使用 `cx1-yuque` 读取正文。按完整标题定位，每个段落到下一个同级或更高层级标题为止。重名时按上级标题消歧。若导出的 Markdown 遗漏图片或文件名，用同一文档的 Lake 正文核对对应范围。
- 按段落中的菜名、做法和照片中可见的食材、容器、摆盘交叉判断。几张图若只是同一道菜的不同角度或特写，归入同一条。仅凭名称相同，不能合并不同做法或不同次烹饪的记录。
- 优先使用日记里的菜名和做法，证据不足时用能确认的名称。全桌合照、非菜品图和无法可靠归属的照片单列，供用户复核。只为可识别的单独菜品建记录。

## 获取照片

对语雀 CDN 原图中支持 OSS 处理的 JPEG，固定请求 `x-oss-process=image/quality,q_90`。使用 [inspect-photos.py](scripts/inspect-photos.py) 批量核对响应与原图。脚本需要 Python 3.8+ 和 ImageMagick 7，逐张给出图片字段可用的数据或具体失败原因。

```bash
python3 "<SKILL_DIR>/scripts/inspect-photos.py" "<图片链接 1>" "<图片链接 2>"
```

用脚本返回的地址直接引用图片，保留原始像素尺寸。有可信文件名时可以用源文件名。体积超出期望时仍使用 `q_90`，记录实际大小。已尝试压缩但未通过核验的照片单列，标明所在段落、照片序号和原因。其他格式或平台的照片按原格式核实，只有目标图片字段支持时才使用。

## 交付和写入

- 预览列出每个名称及所归属的照片（段落内序号或文件名），并单列未归属和处理失败的照片。
- 写入时从当前 shell 读取已导出的 `RECIPE_YUQUE_URI`。用 `cx1-yuque` 检查目标表结构和已有记录，再添加本次可确认的菜品及可用照片。没有可用照片的菜品在结果中标为待补。详细步骤见 [语雀数据表写入](references/yuque-table.md)。
